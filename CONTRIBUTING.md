# Contributing

Read [AGENTS.md](AGENTS.md) and the [active docs](docs/README.md). Discuss a change in an issue first; scope the PR before implementing. Use a feature branch and Conventional Commits / Conventional Commit-style squash PR titles. Link issues accurately (`Refs` versus `Closes`). Keep changes focused, add tests proportionate to risk, and update impacted docs and contracts in the same PR.

Do not include secrets or private user data. Never reset production data or publish content as part of routine CI. Human approval is required for merge, production release and irreversible actions. See [GitHub setup](docs/operations/github-setup.md).
